회의 핵심 결론

1. 메뉴를 완전히 새로 짜기보다 기존 구조를 확장한다

회의에서는 영업·생산·마감 기준으로 메뉴를 세분화하는 구상이 제시되었으나, 완전한 ERP식 재구성은 개발량과 복잡도가 지나치게 커질 수 있다는 의견이 있었다. 따라서 기존 통합관리시스템 구조를 유지하되, 명칭·디자인·권한·첨부·마감 기능을 확장하는 방향이 현실적이다.

2. 가장 먼저 수정할 항목은 “오류 수정”과 “증빙 첨부”다

영업파트 발표에서 톤백이 PS Ball 출고수량으로 잘못 인식되는 오류가 확인되었다. 이는 편의 개선이 아니라 데이터 오류이므로 우선 수정 대상이다. 계근표 이미지 업로드 기능은 마감 시 잔디 검색을 줄이고, 거래처 재요청 대응을 빠르게 하므로 단기 핵심 과제로 정리되었다.

3. 마감파트는 “월말 취합”에서 “발생 시점별 누적 마감”으로 바꿔야 한다

현재 매입·매출 마감자료는 메일, 잔디, NAS, 엑셀, 전자결재에 분산되어 있으며, 담당자가 다시 대조·취합하고 있다. 시스템상 매입관리 목록을 만들고, 지점 또는 담당자가 건별로 증빙을 업로드하면 마감담당자는 같은 화면에서 거래명세서·계산서·품의·영수증을 대조할 수 있어야 한다.

4. 현장에는 관리용 엑셀을 추가로 요구하지 않는다

장비 소모품, 유류, 필터, 수선내역 등은 관리적으로 필요하지만, 현장에 또 다른 엑셀 대장을 만들게 하면 이중·삼중 업무가 된다. 현장은 화이트보드·현장기록 등 최소 방식으로 기초자료를 남기고, 사무실에서 필요한 기준으로 시스템화·필터링하는 방향이 적합하다.

5. 반복업무 자동화의 목적은 인력 대체가 아니라 업무 수준 상승이다

회의 중 가장 중요한 메시지는 반복 입력·대조·취합 업무를 줄여 구성원들이 현장 방문, 감사, 홍보, 데이터 분석, 개선제안 등 더 높은 수준의 업무를 할 수 있어야 한다는 점이었다. 시스템 구축은 단순 전산화가 아니라 업무문화 전환의 계기다.

구분 문제 회의에서 나온 개선 방향

수기 입력 오류 판매 수량 입력 오류가 월마감 때 반복 확인됨 계근표·판매입력·마감자료 대조 가능하게 설계

2.2 PS Ball 현황과 전일재고 연동

핵심 문제

현재는 전일 재고, 생산량, 출하량, 파포 등을 엑셀에서 계산한 뒤 결과값을 다시 시스템에 넣는 흐름이 존재한다. 이는 시스템 구축 취지와 맞지 않는다.

flowchart LR
    A[전일 재고] --> B[당일 생산]
    B --> C[파포/손실]
    C --> D[출하량]
    D --> E[당일 재고]
    E --> F[다음날 전일 재고 자동 반영]
개선 요구 설명
전일 재고 자동 불러오기 새 입력 시 전날 수치를 기본값으로 표시
계산식 내장 전일재고 + 생산 - 출하 - 파포 등 계산
결과값 자동 산정 사용자가 결과만 수기로 옮기지 않도록 함
Bag/Ton 동시 관리 긴급 발주 판단을 위해 Bag 단위 필요 여부 검토
SIZE 정렬 소형 → 대형 순 정렬

2.3 인원·잔업·근태

항목 현재 구조 개선 방향
출퇴근 캡스 자료 기반 입력 기준자료를 캡스로 둘지 시스템 입력으로 둘지 명확화
잔업 지점, 환경관리팀, 총무팀 반복 확인 가능 책임 구간과 최종 기준자료 설정
첨부자료 캡스 이미지 첨부 가능성 논의 매일 첨부할지, 특이사항 때만 첨부할지 결정 필요

2.4 장비·유류·소모품

항목 회의 정리
장비 사용 아워미터 기반 운행시간 입력 유지
장비 점검 1일/주간 점검 항목은 간소화 필요
유류 관리 경유, 윤활유, 기어유 등은 한 곳에 모으고 필요 시 필터링
장비 펀치리스트 고액 수선·장비 유지보수 이력은 관리 필요
소모품 수불 현장에 추가 엑셀을 만들기보다, 시스템상 장비별 소모품/수불내역으로 정리
현장 기록 화이트보드 등 간단 기록 후 2~3일 내 시스템 반영
운영 원칙

현장은 현장 일을 해야 하므로, 관리자가 필요한 자료를 이유로 현장에 동일 데이터를 여러 번 입력시키지 않는다. 필요한 관리자료는 시스템에서 필터링·추출한다.

회고

이번 회의는 “무엇을 만들 것인가”보다 “왜 만들어야 하는가”가 더 중요했다. 통합관리시스템은 회사가 외부 ERP를 도입하지 못하는 현실에서 내부 업무를 스스로 표준화하기 위한 도구다. 제대로 만들려면 개발자가 모든 것을 알아서 해주는 방식이 아니라, 실제 담당자들이 자신이 반복해서 하는 일, 자주 틀리는 일, 매번 찾는 자료, 월말에 몰리는 자료를 구체적으로 꺼내야 한다.

1차 회의의 성과

영업·생산·마감 각 파트가 “문제가 있다”는 수준을 넘어, 어떤 자료가 중복되고 어떤 자료가 기준자료가 되어야 하는지 말하기 시작했다. 이것이 통합관리시스템 구축의 출발점이다.
